# Анализатор журналов событий (CLI, Java)

Консольная утилита на Java: читает журнал событий **построчно** (файл целиком в память не
загружается), фильтрует записи, считает сводку и сохраняет отчёт в JSON или CSV.

Реализация максимально простая: только JDK, без сборщиков и без библиотек в основном коде.

## Бизнес-требования

Службе поддержки нужно быстро находить частые ошибки и их источники в журналах нескольких
компонентов. Для этого нужен CLI-анализатор, который:

- принимает путь к файлу и параметры через командную строку;
- читает журнал построчно и не хранит все строки в памяти;
- фильтрует события по интервалу времени (начало включительно, конец исключительно),
  уровню и источнику;
- считает корректные и повреждённые строки, события после фильтрации, сводки по уровням и
  источникам, top-N кодов событий;
- печатает сводку в терминал и сохраняет её в JSON или CSV;
- понятно обрабатывает пустой и отсутствующий файл;
- для каждой повреждённой строки показывает её номер и причину.

## Формат журнала и правила разбора

```
timestamp | level | source | eventCode | message
```

Пример:

```
2026-09-01T00:08:59Z | WARN | auth-api | AUTH_LOGIN_OK | User session created
```

Строка считается **корректной**, если одновременно выполнено:

- ровно 5 полей, разделитель — `|` (символ `|` внутри полей запрещён);
- `timestamp` — ISO 8601 UTC c обязательным `Z` (`2026-09-01T00:08:59Z`);
- `level` — один из `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR` (строго в верхнем регистре);
- все пять полей непустые (пробелы по краям полей обрезаются).

Остальные строки (в том числе пустые) считаются повреждёнными: обработка не прерывается,
строка учитывается в счётчике ошибок, а в stderr выводится её номер и причина.

В приложенном `logs_events_sample.log` — 1209 строк: 1200 корректных и 9 намеренно
повреждённых (неверная дата, неизвестный уровень, пустые поля, лишний/недостающий
разделитель, пустая строка).

## Требования к окружению и установка

Проверено в WSL (Ubuntu 24.04) с OpenJDK 21. Нужны `javac`, `java`, `curl`, `unzip`.

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk-headless curl unzip
java -version   # openjdk version "21..."
```

Зависимости:

- основной код — только JDK, внешних зависимостей нет;
- тесты и покрытие — JaCoCo 0.8.12. Он не входит в репозиторий: `build.sh` один раз
  скачивает архив с Maven Central в `lib/jacoco/` (нужен интернет при первой сборке).

## Сборка, тесты и отчёт о покрытии — одна команда

```bash
cd log-analyzer
./build.sh
```

Скрипт компилирует `src/main/java` и `src/test/java`, запускает тесты под агентом JaCoCo,
строит отчёты и падает с ненулевым кодом, если тесты не прошли или покрытие строк ниже 80%.

Артефакты:

| Путь | Что это |
| --- | --- |
| `build/classes` | скомпилированное приложение |
| `build/report/index.html` | **HTML-отчёт по тестам и покрытию** |
| `build/coverage.csv` | покрытие по классам (для машинной проверки) |

## Запуск

```bash
java -cp build/classes loganalyzer.Main --input logs_events_sample.log
java -cp build/classes loganalyzer.Main --help
```

### Параметры CLI

| Параметр | Обязательный | Описание |
| --- | --- | --- |
| `--input <файл>` | да | входной журнал |
| `--from <время>` | нет | начало интервала включительно: ISO 8601 UTC или `ГГГГ-ММ-ДД` (начало суток UTC) |
| `--to <время>` | нет | конец интервала исключительно, формат тот же |
| `--level <уровень>` | нет | `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`; регистр не важен |
| `--source <имя>` | нет | точное имя источника, например `gateway` |
| `--top <N>` | нет | сколько кодов событий показать, по умолчанию `5` |
| `--format <json\|csv>` | нет | формат файла отчёта, по умолчанию `json` |
| `--output <файл>` | нет | куда сохранить отчёт; без параметра файл не пишется |
| `--help`, `-h` | нет | справка |

`--format` влияет только на файл, создаваемый `--output`. Сводка в терминал печатается всегда.

Коды выхода: `0` — успех, `2` — неверные аргументы или проблема с входным файлом,
`3` — ошибка чтения/записи.

## Примеры

### 1. Только ошибки, топ-3 кода событий

```bash
java -cp build/classes loganalyzer.Main \
    --input logs_events_sample.log --level ERROR --top 3
```

```
Файл: logs_events_sample.log
Фильтр: from=-, to=-, level=ERROR, source=-
Строк всего: 1209
Корректных строк: 1200
Ошибочных строк: 9
Событий после фильтра: 475

По уровням:
  ERROR — 475

По источникам:
  payment-worker — 180
  orders-api — 120
  gateway — 86
  inventory-api — 52
  auth-api — 37

Топ-3 кодов событий:
  1. PAYMENT_TIMEOUT — 97
  2. ORDER_REJECTED — 88
  3. HTTP_502 — 86
```

### 2. Комбинация фильтров и JSON-отчёт

```bash
java -cp build/classes loganalyzer.Main \
    --input logs_events_sample.log \
    --from 2026-09-02 --to 2026-09-03 \
    --source gateway --level ERROR --top 3 \
    --output examples/report.json
```

За сутки 2026-09-02 ошибок `ERROR` от `gateway` — 6, все `HTTP_502`. Файл
`examples/report.json`:

```json
{
  "input": "logs_events_sample.log",
  "filters": {"from": "2026-09-02T00:00:00Z", "to": "2026-09-03T00:00:00Z", "level": "ERROR", "source": "gateway"},
  "lines": {"total": 1209, "valid": 1200, "invalid": 9},
  "matched": 6,
  "byLevel": {"ERROR": 6},
  "bySource": {"gateway": 6},
  "topEventCodes": [{"eventCode": "HTTP_502", "count": 6}],
  "invalidLines": [
    {"line": 36, "reason": "timestamp не в формате ISO 8601 UTC: 'not-a-timestamp'"},
    {"line": 161, "reason": "неизвестный уровень 'NOTICE'"},
    ...
  ]
}
```

`invalidLines` — сведения обо всём файле, а не только о событиях после фильтра.

### 3. CSV-отчёт по всему журналу

```bash
java -cp build/classes loganalyzer.Main \
    --input logs_events_sample.log --format csv --top 3 --output examples/report.csv
```

```
section,key,count,reason
summary,total_lines,1209,
summary,valid_lines,1200,
summary,invalid_lines,9,
summary,matched_events,1200,
level,ERROR,475,
...
invalid_line,36,1,timestamp не в формате ISO 8601 UTC: 'not-a-timestamp'
```

## Формат отчётов

**JSON:** `input`, `filters` (`from`, `to`, `level`, `source`), `lines` (`total`, `valid`,
`invalid`), `matched` (событий после фильтра), `byLevel`, `bySource`, `topEventCodes`
(`eventCode`, `count`), `invalidLines` (`line`, `reason`).

**CSV:** плоская таблица `section,key,count,reason`; `section` — `summary`, `level`,
`source`, `event_code`, `invalid_line`.

Во всех отчётах записи отсортированы по убыванию количества, при равенстве — по алфавиту,
поэтому результат детерминирован.

## Структура проекта

```
src/main/java/loganalyzer/
  Event.java       запись журнала
  LogParser.java   разбор и проверка строки
  Filter.java      фильтр: интервал, уровень, источник
  Stats.java       построчное чтение и агрегация
  Report.java      сводка в терминал, JSON и CSV
  Main.java        CLI: аргументы, коды выхода
src/test/java/loganalyzer/Tests.java   тесты и мини-раннер
build.sh                               сборка + тесты + покрытие
logs_events_sample.log                 приложенный журнал
examples/                              примеры отчётов и вывода
```

Файл обрабатывается потоково (`BufferedReader.readLine()`); в памяти хранятся только
счётчики и номера повреждённых строк с причинами — сами строки не сохраняются.

## Тестирование

`./build.sh` запускает 103 проверки без внешних тестовых библиотек:

- корректные и повреждённые записи: неверная и невозможная дата, дата без `Z`, неверный
  уровень, пустые поля, 4 и 6 полей, пустая строка, `null`;
- нормализация пробелов и сообщения с запятыми/кавычками;
- фильтры по отдельности и в комбинации, границы интервала (включительно/исключительно);
- счётчики строк, номера и причины повреждённых строк, сводки по уровням/источникам/кодам,
  top-N и порядок при равных количествах;
- CLI: справка, отсутствующие/неизвестные параметры, неверные значения, коды выхода,
  отсутствующий файл, каталог вместо файла, ошибка записи отчёта;
- пустой файл, файл только из повреждённых строк, детерминированность JSON;
- JSON/CSV: структура, экранирование кавычек, запятых, переводов строк и управляющих
  символов;
- большой файл (20 000 строк) — проверка потоковой обработки.

**Метрика покрытия:** покрытие строк JaCoCo
`LINE_COVERED / (LINE_MISSED + LINE_COVERED)` — **264 из 267 строк (98.9%)** при пороге 80%,
который проверяется в `build.sh`. Из подсчёта исключены только тестовые классы (они не
передаются в `--classfiles`); весь основной код в подсчёте. Непокрытыми остались строки
запуска `main()`/`System.exit()` и одна ветка экранирования CSV.

HTML-отчёт: **`build/report/index.html`** (открыть в браузере).

## Принятые решения и ограничения

- `timestamp` — строго ISO 8601 UTC с `Z`; смещения вида `+03:00` считаются ошибкой формата.
- `level` в файле — строго в верхнем регистре; регистр параметра `--level` не важен.
- Пустое поле (включая `message`) делает строку повреждённой; пустая строка — тоже ошибка.
- `byLevel`, `bySource`, `topEventCodes` считаются по событиям **после** фильтрации;
  `lines` и `invalidLines` — по всему файлу.
- `top-N` — по всем кодам событий после фильтра (не только по уровню `ERROR`).
- Если `--from` не раньше `--to`, CLI сообщает об ошибке (пустой интервал).
- Если `--output` не указан, `--format` ни на что не влияет: сводка только печатается.
